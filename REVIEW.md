# REVIEW.md

Review of the starter `app/main.py`. Every defect below was reproduced and then fixed in the
rewritten file. "Notice" gives a concrete input/symptom; "Fix" gives what the current code does.

| # | Where (function) | What is wrong | How you'd notice it | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` setup | Client is created without `tz_aware=True`, so PyMongo returns **naive** datetimes. Every later IST/UTC calculation is then ambiguous. | Any analytics or `late`/`overtime` math silently uses naive local time; dates near midnight land on the wrong day. | Create the client with `tz_aware=True, tzinfo=timezone.utc`; all stored instants come back as UTC-aware. |
| 2 | `compute_late_minutes` | Treats `punch_in` as if its wall-clock equals IST: `punch_in.replace(hour=h, minute=m,...)` builds "shift start" in whatever tz the naive datetime happens to be. No IST conversion, no R1 truncation to whole seconds. Also the grace test `minutes > 10` compares floored **minutes**, so 10:00:30 (just over grace) yields 10 but 10:00:00..10:00:59 all floor to 10, hiding the strict ">10:00 seconds" boundary. | Shift 09:30, punch 09:40:01 should give 10; starter gives 0. Punch 09:40:00 should give 0. | Build shift start from the record's IST **date string**, convert to UTC, compare on **seconds** (`delta <= 600 -> 0`), then `floor(delta/60)`. Instants truncated to whole seconds in `ms_to_dt`. |
| 3 | `compute_work_hours` | Uses Python `round()` which is **banker's rounding** (round-half-to-even), not R4's half-up. | `round(2.675, 2)` style inputs round the wrong way; e.g. a work span of 4.125h → 4.12 vs required 4.13. | `round_half_up()` using `Decimal(str(x)).quantize(..., ROUND_HALF_UP)`. |
| 4 | `compute_overtime` | Three bugs: (a) ignores R3's **30-minute minimum** (`max(0, minutes)` counts 5 min as 5); (b) `datetime.fromisoformat(date_str).replace(tzinfo=IST)` tags a date-only value as IST but subtracts a differently-zoned `punch_out`; (c) for an **overnight** shift the shift end is on the *next* calendar day, which it never accounts for. | A 5-minute overtime returns 5 (should be 0). Overnight 22:00–06:00 punch-out computes negative/garbage overtime. | New `shift_end_dt()` builds end from the date in IST→UTC and adds a day for overnight shifts; overtime is `floor` minutes, returned only when `>= 30`. |
| 5 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) is a **race**: two concurrent creates both pass the check and both insert. `created_at = datetime.now()` is naive **local** time. No unique index. No `shift_start != shift_end` check, no email/`emp_code` pattern validation. Returns the mongo doc, risking `_id` leakage. | Fire two identical POSTs in parallel → two 201s and a duplicate `emp_code`. `created_at` is wrong by the host's tz offset. | Unique index `uq_emp_code`; insert and catch `DuplicateKeyError` → 409. `created_at = datetime.now(tz=UTC)`. Pydantic enforces patterns and `shift_start != shift_end`. Response built by `serialize_employee` (never exposes `_id`). |
| 6 | `list_employees` | `skip = page * page_size` skips a whole page (page 1 skips the first 20). `total = count_documents({})` ignores the `department` filter. No sort → undefined order (contract: `emp_code` asc). No bounds on `page`/`page_size`. | `GET /employees?page=1` hides the first 20 rows. `total` doesn't match a filtered list. | `skip=(page-1)*page_size`; `count_documents(q)` on the filtered query; `.sort("emp_code", ASCENDING)`; `page>=1`, `1<=page_size<=100` via FastAPI `Query`. |
| 7 | `punch_in` | `emp["shift_start"]` with no 404 guard → unknown employee throws `KeyError` → **500** (contract wants 404). Check-then-insert race for the daily record. `datetime.fromtimestamp(ms/1000)` uses naive local tz. No R1 overnight date rule. No epoch-ms validation (seconds/floats/strings accepted). Writes a non-contract `id` field. `status` not restricted to the three presence values. | Punch-in for a missing employee → 500. Two parallel punch-ins → two 201s. A seconds value like `1783312500` is accepted. | 404 when employee missing; unique index `uq_emp_code+date` + `DuplicateKeyError` → 409; `ms_to_dt` (UTC, truncated to seconds); `attendance_date_for_punch` implements R1 incl. overnight; `StrictInt` + range check reject non-ms; status validated to `{PRESENT,WFH,ON_DUTY}`; no `id` in the response. |
| 8 | `list_attendance` | Loads the **entire** collection into memory (`list(find(q))`) then sorts and paginates in Python — dies on 100k docs and ignores indexes. Sorts only by `date` (contract: `date` desc, then `emp_code` asc). No `date_from > date_to` → 422. Returns `id`, and raw datetimes instead of epoch ms. | At 100k records the endpoint is slow/heavy; two records on the same date come back in arbitrary order. `date_from=2026-02-01&date_to=2026-01-01` returns 200 instead of 422. | DB-side `.find(q).sort([(date,-1),(emp_code,1)]).skip().limit()`, backed by the `date_empcode` index; `count_documents(q)` for `total`; 422 when `date_from > date_to`; `serialize_attendance` emits epoch ms and no id. |
| 9 | all responses | Instants were returned as Python/BSON datetimes, and `_id`/`id` were exposed. The contract requires **epoch milliseconds** everywhere and forbids any id. | A client reading `punch_in` gets an ISO string / object, not an int; `id` appears in payloads. | Central `dt_to_ms` + `serialize_*` helpers convert at the boundary; `history` time fields inside `changes` are converted too (easy to miss). |
| 10 | startup | No indexes are ever created; the seeded DB has only `_id`. List/analytics would COLLSCAN. | `explain` shows COLLSCAN; slow at scale. | `@app.on_event("startup") ensure_indexes()` creates all needed indexes idempotently (`create_index` is a no-op if they exist). |
| 11 | `/health` | Always returns `{"status":"ok"}` without touching MongoDB, so it can report healthy while the DB is down (contract: 200 only if a ping succeeds, else 503). | Stop MongoDB → health still 200. | `db.command("ping")` wrapped in try/except; 503 on failure. |

## Looked at and judged **not** a defect
- **`IST = timezone(timedelta(hours=5, minutes=30))`** is correct and reused as-is.
- **Reading `MONGO_URI`/`MONGO_DB` from the environment with `load_dotenv()`** is fine; real env vars already take priority over `.env` with python-dotenv's default (`override=False`). Kept.
- **Defaulting `shift_start`/`shift_end` to 09:30/18:30** matches the OpenAPI schema defaults. Kept.
- The helper **signatures** were a reasonable starting point, but each body had to be rewritten (see 2–4); they are reused only in corrected form.
